TL;DR

BridgeVLA makes 3D manipulation learning data-efficient by aligning both ends of a pre-trained VLM: point clouds are rendered into multi-view orthographic images, and actions are predicted as 2D heatmaps in that same image space. BridgeVLA++ adds a unified spatio-temporal memory — temporal memory keeps the interaction history to decide what to do next, spatial memory re-renders earlier, less-occluded geometry to decide where exactly to act — reaching state of the art on memory-dependent manipulation without giving up the data efficiency or out-of-distribution generalization of the base model.

Abstract

Leveraging pre-trained vision-language models (VLMs) to construct vision-language-action (VLA) models has emerged as a promising paradigm for 3D robot manipulation. However, existing 3D VLA methods remain data-hungry, generalize poorly to distribution shifts, and lack explicit memory of past observations. These limitations hinder their application to data-scarce, open-world and memory-dependent manipulation scenarios. In our previous work, BridgeVLA improves data efficiency and generalization by preserving the input–output alignment of a pre-trained VLM during 3D action learning: raw point clouds are projected into multi-view images, and intermediate heatmaps are predicted before generating robot actions.

In this work, we further extend BridgeVLA with a unified spatio-temporal memory architecture that models persistent spatial context and temporal interaction history. The resulting memory-augmented framework can reason over historical observations while preserving the hallmark data efficiency and strong generalization capability of BridgeVLA. Extensive experiments show that our framework establishes a strong foundation for spatial manipulation tasks and robust generalization (evaluating the base BridgeVLA on RLBench, COLOSSEUM and GemBench). When equipped with the unified spatio-temporal memory, BridgeVLA++ further achieves state-of-the-art performance on two challenging memory-dependent manipulation benchmarks without sacrificing the data efficiency and generalization of the original BridgeVLA. In addition, BridgeVLA++ extends effectively to bimanual manipulation and is validated on a new real-world robot embodiment, demonstrating its scalability across tasks, environments and robot embodiments. These results establish BridgeVLA++ as a unified 3D vision-language-action framework that simultaneously supports data-efficient learning, robust generalization and memory-aware robot manipulation.

How it works

Method

From input–output alignment to a unified spatio-temporal memory.

Part I — BridgeVLA: spatial input–output alignment

A pre-trained VLM is fluent in 2D images and language, not in point clouds and 6-DoF poses. BridgeVLA closes that gap from both sides: the input is rendered back into images, and the output is expressed as heatmaps that live in the very same image space.

1

Multi-view orthographic projection

RGB-D observations from calibrated cameras are fused into a colored point cloud and rendered into three orthographic views (top, front, right), following RVT / RVT-2. The VLM sees only images and language — no proprioceptive state is injected into its forward pass, which keeps the input distribution close to pre-training.

2

2D-heatmap pre-training

Before any robot data is touched, the VLM (PaliGemma: SigLIP + Gemma) is taught to ground language-specified objects as spatial heatmaps on the 120K object-detection split of RoboPoint. Output image tokens are rearranged into a patch grid and decoded by a convex-upsampling module, supervised with a cross-entropy loss against truncated Gaussian targets.

3

Coarse-to-fine 3D action decoding

Candidate 3D locations are scored by summing the per-view heatmap values at their projections; the arg-max becomes the next-keyframe translation. A second pass re-renders a zoomed crop around the coarse prediction for precision. Rotation (continuous 6D), gripper state and the collision flag come from a three-layer MLP on pooled global plus local per-view tokens.

Part II — BridgeVLA++: unified spatio-temporal memory

The coarse-to-fine design exposes exactly two stages where past observations help, and they need different things. The coarse stage reasons over the whole workspace and must know what has already happened; the fine stage localizes inside a zoomed crop and must see geometry the arm is currently hiding. BridgeVLA++ therefore injects a different memory at each stage — both in the VLM patch-token space, so the heatmap action interface is unchanged.

𝒯

Temporal memory → what to do next

Injected at the coarse stage as three token banks: initial anchor views (the episode's first render, a fixed global reference), neighbouring keyframes (the most recent n = 2 executed keyframes, short-term context), and sub-goal keyframes (longer-term evidence of completed milestones).

A lightweight adaptive sub-goal gate decides what is worth keeping: a learnable query token pools the memory-conditioned tokens and a small MLP predicts a retention probability, so a frame is stored only when it adds information the memory does not already hold.

𝒮

Spatial memory → where exactly to act

Injected at the fine stage. The colored point cloud of the initial observation, P0, is stored once and — unlike a fixed 2D image — can be re-rendered under any later zoom. Once the coarse stage picks a waypoint, the same crop is applied to both the live cloud and P0, and the reference is re-rendered through the fine-stage virtual cameras.

Because the two share a camera configuration they are aligned view by view, so tokens of each current view attend only to memory tokens of the corresponding reference view: complementary geometry, never a replacement for the live observation.

⇄

Injection & bimanual extension

Each memory-injection block is two attention layers: current tokens are queries, memory tokens are keys/values in cross-attention, then self-attention and a feed-forward fuse the result. The output keeps the input token-grid shape (V×N×d), so the convex-upsampling decoder and action heads run unmodified.

Because both memories describe the scene rather than an arm, bimanual manipulation needs only duplicated upsampling modules and action heads on a shared VLM backbone, shared memories and a shared sub-goal gate.

💡
The memory is strictly additive. It adds 269.77M parameters — 9.2% on top of the 2.92B-parameter backbone — and raises end-to-end latency from 0.51 s to 0.55 s per prediction step (+7.8%) on a single RTX 4090. Temporal entries are cached as already-encoded tokens, so history never costs an extra backbone forward pass.

Two embodiments, ten demonstrations per language instruction

Real-Robot Experiments

A 7-DoF Franka Research 3 for general manipulation, and a held-out 6-DoF DOBOT CR5A for memory.

Memory on a held-out embodiment

The Franka suite is near-saturated, which proves those tasks are solvable from the current frame alone. So the memory is tested on a second, held-out embodiment with three tasks built so that the current observation underdetermines the next action — plus two ordinary pick-and-place families that check the memory costs nothing on tasks that never needed it. All methods train on the same 70 demonstrations (10 per language instruction).

①

Press Button — counting

Press the blue button exactly N times (given in words, “twice” / “three times”), then the yellow button once. A press leaves no visible trace, so every post-press frame is identical up to nuisance variation: the running count exists only in the policy's history. Neither baseline solves a single trial in any setting.

②

Cover Blocks — occlusion

Cover all three blocks, then uncover only the block of the instructed color. Covering erases the color evidence from the scene, so the second phase is solvable only from the colour-to-location bindings formed before the covers went on.

③

Swap Eggplant — rearrangement

Two look-alike eggplants must end up each on the other's initial plate, using a third plate as a buffer that must be empty again at the end. Intermediate configurations recur across phases, so the correct next placement depends on which eggplant has already moved.

Generalization to unseen conditions and instructions

Six generalization settings. Four probe robustness to visual disturbance — Distractor, Lighting, Background, Height — and two probe instruction-level generalization: Combination (object–skill pairings each seen in training, never demonstrated together) and Category (object categories absent from the robot data). BridgeVLA beats RVT-2, the strongest baseline of this suite, in all seven settings, by 32% on average, with the widest margins under Lighting and Combination.

Where it still fails

Category is the one setting whose absolute success rate stays low, and all three failures below come from it. They are not a collapse of the pre-trained grounding — the model still predicts accurate heatmaps on pre-training samples after fine-tuning. Two gaps are more likely: the pre-training images are third-person photographs rather than orthographic projections of a point cloud, and pre-training only ever asks for object localization, while manipulation needs keypoints that sit on no object at all.

A

Predict heatmaps, not coordinates −59.1

Swapping convex upsampling for a parameter-matched Transformer decoder that regresses target positions under an MSE loss collapses RLBench from 90.5% to 31.4%, and the ablated model is markedly harder to optimize (batch 192 vs 64, careful LR tuning). The heatmap gives denser supervision, injects a 3D→2D spatial prior, and shares the spatial structure of the input images.

B

Do not feed 3D positions to the VLM −34.3

Fusing per-pixel 3D positions into the image features through a 3D convolutional module injects richer spatial cues — and drops success from 90.5% to 56.2%, because the image features shift away from the distribution the VLM was pre-trained on. For a pre-trained VLM, input alignment outweighs explicit 3D input.

C

2D-heatmap pre-training carries language generalization

Without pre-training, the policy fails to generalize in both language-related real-world settings (Combination, Category) and cannot even match RVT-2, while the full model is best in both (Figure 4). Fine-tuning on a handful of robot trajectories cannot instil grounding of language semantics in the heatmap space.

D

Continuous 6D rotation beats discretization −2.3

Replacing the continuous 6D rotation head with the discretized per-axis Euler classification of the conference version costs 90.5% → 88.2%, concentrated in tasks demanding precise end-effector orientations. The 6D form also avoids the gimbal lock of discretized Euler angles in near-vertical gripper poses.
